# MambaTV：TV 端 B 站客户端详细开发计划

日期：2026-10-24。状态：未开始实施；本文件仅完成规划。

架构依据：[设计原则与架构](tv-bilibili-architecture.md)。主平台为 Android TV，使用 Flutter + Riverpod + MVVM + 整洁架构。

## 1. 执行策略与发布范围

先把技术风险验证清楚，再按功能纵向交付。每个功能依次完成领域契约、服务与 Repository、必要 UseCase、Riverpod ViewModel、Consumer TV View 和验证，避免先做满模拟页面再集中接接口。ViewModel 使用 Notifier／AsyncNotifier，领域层和数据层通过构造函数接收依赖，保持不依赖 Riverpod。

- M0–M2：验证可行性并完成最小真实播放流程，形成内部 alpha。
- M3–M6：完成登录、内容浏览、播放器与个人列表，形成 beta。
- M7：真机验收、稳定性和发布，达到 v0.1.0。
- M8：字幕、弹幕与内容发现增强，独立作为 v0.2.0。
- M9：直播、番剧等后续功能，逐项重新评估。

在 M0 通过前，不把 media_kit、具体登录协议和最低设备版本写成已验证结论。在 M7 通过前，不把“APK 已生成”称作“TV 可用版本”。

## 2. 工期估算与依赖

以下是具备 Flutter／Android 开发经验的单人全职工作量估算，按 5 天／周。它是规划区间，不是交付承诺；前提是能取得目标设备、测试账号和可用接口。M0 结束后根据实际风险重新估算。

| 阶段 | 交付物 | 前置 | 估算人日 |
| --- | --- | --- | --- |
| M0 | 技术验证、接口证据、设备与依赖基线 | 当前文档 | 3–5 |
| M1 | 架构骨架、TV 壳、焦点与基础设施 | M0 | 4–6 |
| M2 | 游客／已验证会话下的真实播放流程 | M1 | 4–7 |
| M3 | 扫码登录、会话恢复与账号隔离 | M2；登录可行性在 M0 验证 | 4–6 |
| M4 | 首页、搜索、详情、分 P 与分页 | M3 | 5–7 |
| M5 | 完整播放器、换源恢复与续播 | M2、M3、M4 | 6–10 |
| M6 | 本地记录、远端历史、收藏／稍后再看 | M3、M4、M5 | 5–8 |
| M7 | 真机回归、性能、迁移与正式签名 APK | M1–M6 | 5–8 |
| M8 | 字幕、弹幕、UP 列表等增强 | v0.1.0 | 另估 5–10 起 |
| M9 | 直播、番剧、投屏、下载等独立能力 | 对应专项验证 | 分项估算 |

v0.1.0 基础合计 36–57 人日；预留约 25% 接口／设备适配缓冲后为 45–72 人日，约 9–15 个工作周。兼职不能直接按相同日历周期推算。本文不把 AI 辅助或并行实现视为保证缩短工期的依据。

关键依赖链：扫码与媒体资源验证 → TV 基础和焦点 → 真实音视频播放 → 登录与清晰度能力 → 续播／恢复 → 个人数据 → 真机发布。较早开始设备兼容性测试，不把它全部留到最后。

## 3. M0：技术验证与基线（3–5 人日）

目标：确认核心方案可行，减少后续返工。

任务：

- [ ] 确定第一台真实目标设备，记录品牌／型号、Android 版本、ABI、可用内存、输出模式与遥控器按键。
- [ ] 检查 Flutter／Dart、Android SDK、JDK、Gradle 与插件最低要求；锁定可复现工具链，记录当前 Flutter 自定义频道状态。
- [ ] 建立本项目的 Git 基线与忽略规则，排除 build、缓存、本地配置和凭据；本阶段只准备本地版本管理，不默认创建远端仓库或推送。
- [ ] 确定正式 applicationId 与最低 Android 版本；产品显示名暂用 MambaTV，包名必须在正式发布前固定。
- [ ] 获取 PiliPlus 固定提交，记录需要参考的模块；列出直接复用代码、资源与依赖的来源和许可证，避免跟随移动分支。
- [ ] 对候选库解析依赖，记录具体版本、原生库、代码生成工具和 lockfile；不要直接照抄上游 dependency_overrides。
- [ ] 锁定 `flutter_riverpod`、`riverpod_annotation`、`riverpod_generator` 与 `build_runner`／其他生成器的兼容版本；确认选定版本的自动释放、自动重试和页面不可见时的订阅行为。
- [ ] 用临时验证入口完成扫码获取／轮询／用户确认，验证所选协议生成的凭据确实适用于本项目的列表与播放接口。
- [ ] 验证游客热门／搜索／详情／播放；记录哪些能力需要登录，准备明确的游客降级策略。
- [ ] 验证普通 UGC、分 P、独立音视频、必要请求头、地址有效期和可用清晰度。
- [ ] 在目标设备上比较候选引擎关键行为；优先 media_kit，关键能力失败时再针对同一最小案例评估 Media3 适配成本。

建议新增产物：`docs/adr/0001-stack-and-playback.md`、`docs/api-contracts.md`、`docs/device-matrix.md`、`docs/dependency-inventory.md` 和脱敏 fixtures；这些文件在本阶段实际有证据后创建，当前并未生成验证结论。

验收条件：

- [ ] 扫码确认后可获取并校验当前账号；离开验证页可以停止轮询。
- [ ] 至少一条真实普通视频在目标设备有画面、有声音，可暂停和 seek；至少验证一组独立音视频资源。
- [ ] 凭据与接口体系匹配；不能使用一套登录凭据却假设另一套协议自动兼容。
- [ ] 关键端点有来源、日期、必要参数、脱敏样本和失败语义；没有写入秘密或带签名的真实播放链接。
- [ ] 明确首版 Android／ABI 支持范围、引擎选择与未解决问题；尚无真机时只能记录“模拟器验证”，保留真机验收未完成状态。

若扫码或音视频分离不可用，先定位协议／引擎问题并更新 ADR，不能以假登录或静音视频绕过此阶段。实际工作量超出估算时更新后续计划。

## 4. M1：架构骨架与 TV 基础（4–6 人日）

目标：有可运行、可遥控、可注入 Fake 的 TV 应用壳。

任务：

- [ ] 创建 app、core、domain、data、ui 的最小目录与装配入口，保持领域层纯 Dart。
- [ ] 接入 `flutter_riverpod`、`riverpod_annotation`、开发依赖 `riverpod_generator`，以及 go_router、Dio、持久化封装与不可变模型；统一通过 build_runner 生成，不添加 `package:provider`。
- [ ] 根部建立 ProviderScope；在 App 的依赖 Provider 图装配 Repository／UseCase，业务实现不接收 Ref；配置领域类型的依赖入口和 ViewModel 生成声明。
- [ ] 定义 Notifier／AsyncNotifier 的页面状态约定、AsyncValue 与分页／局部 Command 状态，验证参数化 Provider 的页面实例与账号隔离。
- [ ] 为应用级依赖配置 keepAlive 和显式启动订阅；页面级依赖设置自动释放／有限保留，注册请求、轮询和订阅清理，区分隐藏、退出和 dispose。
- [ ] 在 ProviderScope 显式关闭 Provider 构建失败自动重试，数据层只读重试与播放恢复分别管理，避免叠加请求。
- [ ] 定义 Result／Failure、PageSlice、Session 状态及初始仓储接口，不先创建无需求的泛化框架。
- [ ] 配置 Android TV 启动入口、banner、非触屏声明、联网权限、横屏和遥控器连接变化处理。
- [ ] 建立深色 TV 主题、字号／间距 tokens、TvButton、TvVideoCard、TvGrid、加载／空／错误状态。
- [ ] 建立导航／内容／弹层焦点区域；实现按稳定 ID 恢复焦点和懒加载列表项滚动定位。
- [ ] 配置主页、搜索、我的、设置、详情、登录和播放器路由；初期使用明确标注的 Fake 数据。
- [ ] 创建数据库 v1 与迁移测试入口、偏好和安全存储适配器；实现日志脱敏。
- [ ] 将模板计数器测试替换为应用壳与关键焦点测试。
- [ ] 建立独立 ProviderContainer 的 ViewModel 测试和 ProviderScope overrides 的 Widget 测试，注入 Fake 并覆盖释放与依赖失效；自动释放 Provider 在测试期间保持监听。

验收条件：

- [ ] TV 启动器可显示并打开应用；根导航仅用方向键、确认、返回即可完成操作。
- [ ] 无数据、加载失败和弹窗状态不会导致焦点消失；关闭弹窗返回触发项。
- [ ] UI 和 ViewModel 不依赖具体 Repository 实现；domain 不 import Flutter／Riverpod 或插件，data 不 import Riverpod。
- [ ] 同参数共享、不同页面／账号隔离符合设计；页面释放取消任务，Provider 构建失败不触发额外自动重试，测试之间不共享容器状态。
- [ ] 代码生成、静态分析、基础 Widget／领域测试通过，能够构建并安装调试 APK。

## 5. M2：最小真实播放流程（4–7 人日）

目标：从真实内容入口进入播放器，再返回原位置。

任务：

- [ ] 实现最小 Discovery／Video／Playback Repository、DTO 和 Mapper。
- [ ] 建立简单热门列表或搜索入口，支持进入详情和选中一条视频／一个分 P。
- [ ] 实现 StartPlayback、PlaybackEngine 端口及一个真实引擎适配器；Fake 引擎继续用于自动测试。
- [ ] 建立媒体画面宿主，保证渲染绑定与播放命令使用同一引擎实例。
- [ ] 显示 resolving／opening／playing／paused／failed 状态，实现暂停与一次 seek。
- [ ] 实现打开代次、旧回调过滤、返回释放、错误后重试；不自动循环失败请求。
- [ ] PlayerViewModel 使用 Notifier 暴露播放快照和 Command，打开媒体由显式命令完成；Provider 重建／失效不能意外创建第二个引擎或重放视频。
- [ ] 建立首次有效播放进度保存，防止 0 进度覆盖已有记录。

验收条件：

- [ ] 在电视上完成“入口 → 详情 → 有声播放 → 暂停 → seek → 返回”，无需鼠标。
- [ ] 返回后恢复原卡片与滚动位置；再次打开可使用本地记录续播。
- [ ] 连续切换视频至少 20 次，无多路声音、旧视频回调覆盖或返回后的残留播放。
- [ ] 弱网／无权限／不支持媒体可以返回可操作的错误界面。

本阶段仅形成 alpha，不宣称登录、完整清晰度菜单和长时间稳定性已经完成。

## 6. M3：扫码登录与会话（4–6 人日）

目标：完成可长期使用的账号生命周期。

任务：

- [ ] 实现 AuthRepository、SessionRepository、CredentialStore、QrLoginViewModel 与 TV 登录页。
- [ ] 使用 Notifier／不可变登录状态承载扫码流程，创建挑战与轮询由显式命令启动；根部订阅唯一会话来源，登录 UI 使用 Consumer 订阅并消费回跳效果。
- [ ] 显示等待扫描、等待确认、过期、成功、失败状态；以本轮挑战 ID 隔离结果。
- [ ] 实现不可重叠的轮询、退避、刷新二维码、取消与前后台处理。
- [ ] 启动读取凭据，校验后发布会话；协议支持时实现 single-flight 刷新，否则明确要求重登。
- [ ] 登录成功回跳到原页面／原操作；恢复操作前重新确认用户意图和当前账号状态。
- [ ] 实现退出、账号代次、旧请求取消和私人缓存隔离；首版只保留一个活动账号。
- [ ] 更新会话与账号代次后再使账号相关 Provider 失效；验证仍被监听而重建的 Provider 只读取当前账号，路由回跳只消费一次。
- [ ] 建立匿名／登录／失效／网络暂不可用状态的能力展示策略。

验收条件：

- [ ] 扫码登录后重启仍能恢复有效会话；真实失效后能重新扫码。
- [ ] 取消、过期后刷新、后台返回、网络失败不会留下多个轮询或错误登录。
- [ ] 并发鉴权失败只产生一次刷新流程，单个请求不无限重放。
- [ ] 超时不会被误判成退出；退出后迟到响应不会恢复上一账号。
- [ ] 日志、数据库、fixtures 和路由参数不含真实凭据；安全存储不可用时给出可操作错误。

## 7. M4：内容发现、搜索与详情（5–7 人日）

目标：用户可以稳定地找到想看的普通视频。

任务：

- [ ] 实现推荐／热门及登录条件降级；分别处理分页、重复项和结束标识。
- [ ] 实现输入、主动提交搜索、搜索历史、结果列表和后续分页；自动建议不是首版依赖。
- [ ] 新搜索取消／淘汰旧请求，快切分类不会被旧结果覆盖。
- [ ] 首页／详情／列表使用 AsyncNotifier + 不可变状态；搜索输入与结果按需要分离，Provider 参数使用稳定页面实例、查询／内容和账号标识，保留分页内容和局部失败状态。
- [ ] 实现详情、播放／继续播放、UP 信息、分 P、相关视频和个人列表操作入口。
- [ ] 完成图片占位、失败替代、有限预加载、解码尺寸限制与缓存容量配置。
- [ ] 完成页面加载／刷新／追加加载／空结果／局部失败的独立 UI 状态。
- [ ] 验证系统中文输入法打开、输入、关闭与遥控器焦点恢复。

验收条件：

- [ ] 仅用遥控器完成中文搜索、分页、详情、分 P 播放与返回。
- [ ] 连续浏览至少 10 页或到实际列表末尾，数据无重复追加、请求不重叠、焦点可达。
- [ ] 输入关键词 A 后立即提交 B，即使 A 更晚返回，也只显示 B 的有效结果。
- [ ] 网络中断保留已加载内容；用户可明确重试，加载状态不抢焦点。
- [ ] 无效／已删除视频提供返回路径，不能永久停在 loading。

## 8. M5：播放器完整交互与恢复（6–10 人日）

目标：播放器达到日常观看要求。

任务：

- [ ] 完成控制条显隐、确认播放／暂停、左右 seek、倍速、音轨、清晰度与分 P 选择。
- [ ] 确定画面区、控制条与弹层的按键优先级，避免一键触发多个动作。
- [ ] 串行管理 seek、换清晰度、换音轨与换集；保存位置、倍速、音量和暂停意图。
- [ ] 实现播放结束、下一 P、最后一 P 停止规则；连续播放提供可关闭选项。
- [ ] 对过期链接、CDN 故障、鉴权错误、解码不支持采用分别受限的恢复策略。
- [ ] 以当前账号和设备能力生成菜单；不可用清晰度给出可理解原因。
- [ ] 实现本地进度节流写入、暂停／退出保存、完成判定和无有效时间轴时的保护。
- [ ] 处理系统 Home、后台、休眠、音频焦点及遥控器重新连接，防止恢复后重播或双重播放。
- [ ] 通过 profile／release 模式观察播放画面与 UI 性能，避免用 debug 性能作为结论。
- [ ] 通过细粒度 Provider／select 隔离进度与控制条刷新；覆盖 Consumer 暂停订阅、路由遮挡、依赖重算，正常退出显式保存并关闭，onDispose 仅作兜底。

验收条件：

- [ ] 独立音视频内容可连续播放至少 30 分钟，seek 后口型／声音无持续可感知不同步，并记录样本与设备。
- [ ] 在至少两个可用档位间切换清晰度，恢复位置误差目标不超过 2 秒；不支持时必须记录并修复或限定支持范围。
- [ ] 切换前为暂停状态，切换完成后仍保持暂停；快速换集不会串音或写错进度。
- [ ] 人为失效资源可限次重新解析并恢复；永久错误停止重试并提供操作。
- [ ] 正常重启续播，正常退出位置误差目标不超过 2 秒；强杀场景最近写入损失目标不超过 5 秒加存储调度余量，单独记录实测。
- [ ] 后台／前台与休眠恢复各重复 10 次，无后台残留音频、崩溃或不可恢复黑屏。

## 9. M6：观看记录与个人列表（5–8 人日）

目标：完成账号内容与本地续播的实用流程。

任务：

- [ ] 本地历史按最近观看排序，支持继续播放、删除和清空。
- [ ] 远端历史单独分页展示；按验证结果接入远端心跳，和本地进度写入分开调度。
- [ ] 实现收藏夹列表、夹内视频、稍后再看及各自空状态。
- [ ] 实现添加／移除收藏、添加／移除稍后再看；操作执行中禁用重复提交。
- [ ] 写结果不确定时读取最终状态并提示，不能盲目重放。
- [ ] 实现账号隔离、缓存失效、退出清理；游客记录不自动上传或迁移。
- [ ] 写命令成功后按需刷新相关个人列表 Provider；待确认结果不重复提交，Provider build／失效不得重放收藏等写动作。
- [ ] 设置页提供默认倍速／画质、连续播放、缓存清理、退出登录和关于入口。

验收条件：

- [ ] 收藏／稍后再看变更可在重新拉取后确认，详情与个人页显示一致。
- [ ] 离线本地历史可读取和续播，远端列表明确显示缓存或失败状态。
- [ ] 登录账号 A、退出进入游客、再登录账号 B，不出现 A 的私人列表、搜索记录或迟到请求结果。
- [ ] 本地历史不会因远端请求失败被清空；旧远端进度不会覆盖有效本地续播。
- [ ] 数据库升级测试证明旧版进度保留；清缓存操作不误删安全凭据或观看记录。

## 10. M7：真机验收与 v0.1.0 发布（5–8 人日）

目标：获得有证据支持的 TV 发布候选版本。

任务：

## 11. M8／M9：后续迭代

M8 建议先字幕、后弹幕，再扩展 UP 视频与关注内容：

1. 字幕：验证来源和格式，完成轨道选择、大小、位置、关闭及 seek／变速同步。
2. 弹幕：验证分段／解析，完成按播放时间加载、屏幕密度、避让、样式与性能限制。
3. 大数据解析在必要时放入 isolate；弹幕关闭必须停止不必要的解码／渲染。
4. 在最低目标设备上对照弹幕开关测量帧耗时，必要时自动降低密度；不能拖累视频播放。
5. UP 列表、关注内容与点赞／投币分别建立接口证据、遥控器流程和状态测试。

M9 的直播、番剧、投屏、下载和多账号分别先做专项验证，再建立里程碑；不把它们藏进 v0.1.0 的验收范围。

## 13. 测试与设备矩阵

| 环境 | 主要用途 | 不能替代 |
| --- | --- | --- |
| Windows 键盘开发 | 快速调试 UI、领域逻辑和基础焦点 | TV 启动器、Android 插件、硬解 |
| Android TV 模拟器 | 遥控器导航、页面、Manifest、路由 | 实机 SoC 与解码器兼容性 |
| 主目标真机 | 播放、账号、休眠、音频焦点、遥控器和性能 | 其他型号的兼容性 |
| 第二台不同硬件 | 覆盖不同 Android／ABI／解码器 | 未实际测试的全部电视 |

必须记录的维度：

- 输出：720p、1080p、4K 的布局与安全区；视频 4K 解码作为独立可选能力验证。
- 输入：普通方向键、确认、返回、长按、按键重复、遥控器断开重连、中文输入法。
- 内容：普通 UGC、分 P、短／长视频、失效／无权限视频、两种实际可用清晰度、独立音视频。
- 网络：正常、断网、超时、限流、地址失效；不在公开 CI 对真实服务制造高频故障流量。
- 生命周期：首次安装、冷启动、前后台、休眠、强杀重启、升级、退出账号再登录。

性能初始目标（目标设备 profile／release 实测后可调整，但必须留记录）：

| 指标 | 初始验收目标 |
| --- | --- |
| 按键至焦点反馈 | P95 不超过 100 ms，至少采样 100 次 |
| 60Hz 下列表滚动 | UI／raster 帧耗时 P95 各不超过约 16.7 ms，保留 DevTools 采样；低刷新率另列目标 |
| 公共 H.264 样本首帧 | 受控网络 10 次，P95 不超过 5 秒；同时记录网络耗时与解析／解码耗时 |
| 本地续播 | 正常退出恢复误差目标不超过 2 秒；强杀按 M5 单列结果 |
| 稳定性 | 2 小时连续播放、20 次进入／退出、10 次前后台；无崩溃或重复音频 |
| 内存 | 20 次进入／退出后，在固定等待与同样采样条件下对比，资源不持续线性增长；M0 定义具体机型预算 |

UI 帧耗时、视频掉帧和音画同步分别观察，不能仅以 Flutter 帧率判断视频解码稳定性。

## 15. 风险与应对

| 风险 | 发现时机 | 应对 |
| --- | --- | --- |
| 登录凭据与播放接口不兼容 | M0 | 固定一致协议，验证完整流程再实施 |
| 媒体插件对 B 站资源／电视硬解不兼容 | M0/M2 | 最小样本定位，必要时切换引擎适配器 |
| 上游定制分支难复现 | M0 | 优先维护版本，确需补丁则固定提交并保留回归样本 |
| 风控、限流、接口变化 | 各阶段 | 有限重试、契约适配、游客降级／重新登录 |
| Provider／网络／业务层重试叠加 | M1 起 | 根部关闭 Provider 自动重试，统一只读网络策略，写操作显式提交 |
| Provider 重算重复创建播放／扫码任务 | M1–M5 | build 保持可重复初始化，显式 Command、播放代次和释放测试 |
| 路由隐藏但任务仍在执行 | M1/M3/M5 | 业务显式处理可见性与生命周期，不只依赖自动释放 |
| TV 中文输入体验受设备影响 | M1/M4 | 实测系统输入法，后续可增加手机辅助输入 |
| 弱硬件内存／渲染压力 | M1 起 | 有限缓存、图片尺寸控制、懒加载、可关闭增强效果 |
| 新账号读取旧账号状态 | M3/M6 | ownerKey 隔离、账号代次、取消和迟到结果过滤 |
| 进度初始化／换集竞态 | M2/M5 | 有效进度保护、播放代次、串行命令与测试 |
| 范围不断扩大 | 每阶段 | 按版本验收；直播／番剧／下载各自立项 |
